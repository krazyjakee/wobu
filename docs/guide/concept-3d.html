Making images

Concept 3D

The current 3D tab views and exports completed meshes already present in a project. The turnaround-to-mesh creation flow below is planned, not reachable UI.

View/export only in the current build

Wobu cannot yet review and reroll a completed turnaround or start reconstruction from the UI. Those controls, job orchestration, and automatic handoff to the viewer are tracked in #110.

The planned creation pipeline

  1. Planned — generate a turnaround. Pick the Turnaround preset on a character, creature or prop. It emits eight views on a locked seed.
  2. Planned — review the sheet. The 3D tab (⌘4) shows the turnaround as a set. Views that came out inconsistent can be re-rolled individually before you spend money on reconstruction.
  3. Planned — reconstruct. Wobu submits the views to the mesh backend and polls the job. A .glb lands in the project folder when it's done.
  4. Implemented — inspect and export. Existing mesh records open in an inline three.js viewer with a turntable and can be exported for a modeller.

Why the Turnaround preset looks the way it does

Turnaround is not a generic "spin the character" preset. It exists to feed a specific 3D backend whose headline capability is eight-view reconstruction, so it emits exactly the view types that backend names: 

front · left · right · back · top · bottom · left_front · right_front

Each view is one generation with a locked seed and a framing fragment appended, tagged with its view type — so the mesh stage can hand them straight over with no intermediate mapping. That is a much stronger pipeline than single-image-to-3D, and it falls out of the influence engine for free.

Constraints are baked into the preset

The backend accepts PNG and JPEG only for multi-view, needs a minimum side of 128px, and caps the whole payload at 6 MB before encoding. It also wants a plain background, a single object, and the subject filling more than half the frame.

All of that lives in the preset's framing fragments and output settings, so a turnaround can never be generated in a form the 3D stage would reject. You find out at generation time, not after paying for eight images.

Text does not reach this stage

The 3.1 mesh model has no text-and-image conditioning path — image-to-3D and text-to-3D are mutually exclusive. So the compiled prompt does not ride along to the mesh stage.

In practice this costs nothing, because by the time you reach 3D all of your influence has already been baked into the turnaround images themselves. But it does mean the mesh is only ever as good as the views: fix the turnaround before you reconstruct. An inconsistent back view produces a bad mesh, and no amount of prompt work at this stage will help.

Jobs and waiting (planned UI)

The implemented backend protocol is asynchronous — submit, then poll — but #110 still has to connect it to the app's job controls. The planned UI will use the same cancellation and progress model as images and respect the backend's three-job concurrency limit.

Provider results expire within 24 hours. Backend storage downloads completed meshes into the project folder rather than retaining a URL that would rot; automatic UI handoff is part of #110.

Storage

assets/meshes/7b/7b21…04.glb

Content-addressed like every other asset, so meshes dedupe and never conflict on a shared folder. They are also lazy: a .glb is only pulled off the share when you actually open the 3D tab, because a mesh is orders of magnitude larger than a thumbnail and most sessions never need one.

Local versus hosted (planned creation choices)

The backend supports local ComfyUI mesh generation as an explicit alternative to the hosted service. The current UI cannot start either route; when #110 connects them, local will be attractive for cost and privacy but will carry a quality trade:

Local is a different tier, not a fallback

Open weights stop at an earlier version than the hosted model. Running locally gets you a materially older and lower-quality result, not a drop-in substitute for the cloud one. Wobu presents it as a separate quality tier and won't silently fall back to it when a key is missing.

What you get out

The planned creation output is a blockout mesh with optional PBR materials, at a face count you choose. Existing meshes can already be inspected and exported. They are concept geometry: enough to judge proportion, silhouette and scale in three dimensions, enough to hand to a modeller as a reference, and not enough to ship.
