Building the world

Nodes & hierarchy

Species, characters, settings, props, cultures, vehicles — and even the Style Guide and World Canon — are all the same record type. They differ only in kind, which selects an icon, a colour, a set of description sections, and some default relations.

This is why there is exactly one editor to learn. It is also why adding "Factions" or "Technologies" later is a configuration change rather than a new feature. 

Project
├── Style Guide      (singleton, pinned)
├── World Canon      (singleton, pinned)
└── Nodes            (any kind, freely nestable within kind)

The ten kinds

Kind Nests Description sections
Style Guide singleton Medium, Rendering, Line quality, Lighting, Palette, Never
World Canon singleton Era, Tone, Tech level, Materials, Palette, Never
Species yes — sub-species Silhouette, Anatomy, Materials, Palette, Signature, Never
Culture yes Costume, Ornament, Iconography, Weapons, Materials, Palette, Never
Setting yes — Region → City → District Climate, Architecture, Light, Wear, Materials, Palette, Never
Character no Silhouette, Anatomy, Costume, Materials, Palette, Signature, Never
Creature no Silhouette, Anatomy, Materials, Palette, Signature, Never
Prop yes — sets Silhouette, Materials, Wear, Palette, Signature, Never
Environment no Architecture, Light, Climate, Materials, Palette, Signature, Never
Vehicle yes Silhouette, Materials, Wear, Palette, Signature, Never

The sections are what make Enhance useful. A structured description with a Silhouette field and a Materials field lets the prompt compiler pick the right fields for a full-body shot versus a material study. A blob of prose could not.

Two kinds of relationship

Wobu distinguishes nesting from linking, and the difference matters.

Nesting — within a kind

A node's parent is always the same kind as itself. Ember Coast contains Cinder Bay contains the Kiln Quarter. Vashk has a sub-species. A lantern belongs to a prop set. Nesting is what the navigator tree draws, and you change it by dragging.

A parent is treated as an implicit influence of full weight. The Kiln Quarter inherits everything Cinder Bay says, which inherits everything Ember Coast says.

Linking — across kinds

Links are the edges the influence engine actually walks. Each has a role and a weight, and can be disabled for a single generation without touching the world.

styled_by Rendered in this art style. Implicit from the Style Guide.
species_of This character or creature is of that species.
member_of Belongs to that culture, guild or faction.
located_in Lives in, or is found in, that setting.
related_to A general association — a rival, a matching prop, a sibling design.

You set links from the node itself or from the Relations tab, which also shows backlinks: "3 characters inherit from this". Backlinks are how you find out what you're about to break before you edit a species.

What a node holds

Name & summary The summary is one line, shown in tree tooltips and on influence cards.
Raw notes Your Markdown. Never machine-written.
Description The structured, enhanced sections. Editable.
Description state none · enhancing · fresh · edited · stale
Attributes Kind-specific fields — scale, era, biome, material.
Tags Free-form, for filtering.
Cover asset The image shown on cards and in the tree.
Links The influence edges above.

Description state, and staleness

A description goes stale when the raw notes changed, or when something upstream changed, since the last Enhance. Wobu shows a quiet dot and a re-enhance affordance — it never silently regenerates, because regenerating costs your money and might undo an edit you made by hand.

Edited means you changed the machine's description yourself. That is fully supported; Enhance offers a diff-and-accept rather than clobbering your edit.

Creating and organising

  • ⌘N, the + New button at the bottom of the navigator, or right-click → New. You pick a kind, a name, and — for nestable kinds — an optional parent.
  • Duplicate copies notes, description and links. It is the fastest way to make the second of anything.
  • Drag to re-parent. This changes what the node inherits, so it will often mark descendants stale.
  • Delete asks for confirmation and removes the Markdown file. Generations that referenced the node stay on disk — they are write-once history.
Getting the altitude right

The single most common mistake is writing at the wrong level. If a detail is true of every Vashk, it belongs on the species. If it is true only of guild members, it belongs on the culture. If it is true only of Kael, it belongs on Kael.

Put it too low and you repeat yourself and drift. Put it too high and it contaminates everything. When unsure, ask: would this be wrong for a sibling node? If yes, it's too high.
