Making images

Generating

Presets turn one description into the right kind of sheet. Generations are disposable by default; pinning one is what changes the world.

The controls

At the base of the Inspector, under the compiled prompt: output preset, aspect, model, seed, batch count, and the Generate button. ⌘↵ fires it from anywhere.

Aspect negotiation

The dropdown comes from the selected image backend. Wobu repairs an unsupported saved value before it can reach the queue and shows the negotiated ratio and pixel dimensions beside the control. Flexible backends such as ComfyUI use Wobu's curated, validated ratio vocabulary rather than accepting arbitrary text. Scene composition uses the same source (#111).

Output presets

A preset defines section priorities, framing text, aspect and image count. This is how the same node produces a costume plate one minute and a material study the next.

Preset For Emits
Character sheet character, creature Full body, neutral pose, flat light, ×4
Turnaround character, creature, prop 8 named views on a locked seed — see Concept 3D
Portrait study character Head and shoulders, dramatic key light, ×4
Costume plate character, culture Flat-laid garments and gear
Prop orthographic prop, vehicle Three views on neutral ground, with a scale figure
Material study any Close-up surface tiles, ×6
Environment matte environment, setting Wide establishing shot, atmospheric
Interior environment Eye-level, practical lighting

Presets reweight rather than replace. A material study still inherits your Style Guide and World Canon — it just promotes materials to the front and pushes silhouette down.

The job queue

Generations run through a queue with live previews. The status bar shows queue depth, the active model and the last generation time. Jobs are cancellable — a stalled backend or a slow NAS must never present as a frozen app.

The queue also respects each backend's concurrency limits, so Wobu doesn't manufacture its own rate-limit errors.

The Concepts tab

Results land in Concepts (⌘3) on the node they were generated for. Hover a tile for its prompt and seed. Every result carries its full influence snapshot, so you can always see exactly what produced it.

Pinning

Pinning promotes a generated image to a full_ref reference on that entity. From then on it feeds back as conditioning for the next generation — and, because references inherit, for everything downstream of that node too.

This is the flywheel

Iterate cheaply, promote deliberately. Generations are disposable; pinning is a decision. Pin a good Vashk and every Vashk character afterwards starts from a stronger place. It is the main tool for locking a look, and it is why the hundredth character is easier than the first.

Deleting

Delete concept… on a tile takes the result out of Concepts and the Asset Library, and deletes the picture with it — a concept you deleted should not still be sitting in a grid somewhere. Anything you pinned as a reference, or set as a cover, is kept: deleting a result you did not want is not a decision to undo one you did. The receipt is archived rather than erased, so what the generation cost still counts towards project spend.

Forge mode

Forge takes the Inspector's controls and promotes them to full width, with a large result grid. It is for when you are iterating hard on one subject and want to compare twenty variants at once rather than squinting at a 352px column.

  • Variant grids — sweep a parameter across a batch and compare.
  • Seed locking per entity, so re-rolls stay in family instead of producing a different character each time.
  • Replayable snapshots — every result an entity has ever produced stays on its Concepts tab, and opening one reloads the exact stack it was generated from, including layers that have since been rewritten.

Cost and consent

Bring-your-own-key means every call is billed to you, so Wobu is built not to surprise you:

  • The Generate button shows an estimated cost for the batch on paid providers.
  • A local ComfyUI backend shows no cost at all. That asymmetry is the point, and it's a good default.
  • A per-project spend ceiling with a hard stop, because a turnaround loop is exactly the kind of thing that runs two hundred images unattended.
  • Every generation record stores its provider, model and params — so actual spend is reconstructable from the project folder itself.
Watermarking

Images generated through Google's models carry SynthID watermarking. Worth knowing, since this is concept art headed into a production pipeline.

Generation records

Each generation writes one JSON file into the project folder, named by ULID and never modified: 

generations/2026-07/01ARZ3NDEKTSV4RRFFQ69G5FAV.json

It holds the user prompt, the compiled prompt, the negative prompt, the model, params and seed, the output asset IDs, and the influence snapshot. Because records are write-once and ULID-named, two people generating at the same time on a shared folder can never collide — they simply both appear.
