Rebuilding the index is safe

The index holds no canonical data — it is a cache of what's already in the Markdown. Delete it or rebuild it and nothing is lost; the next open just takes longer. If search results look wrong or a file seems stuck, rebuild before you investigate anything else.

On-disk layout

A project is a self-contained folder, not a database file. Put it on a NAS, a USB stick, or in git. 

Ashfall.wobu/
├── project.json                  id, name, schema version, provider selection
├── nodes/
│   ├── style-guide/
│   ├── world-bible/
│   ├── species/vashk.md          YAML frontmatter + notes + description
│   ├── culture/ember-guild.md
│   ├── setting/cinder-bay.md
│   ├── character/kael-vantris.md
│   ├── creature/  prop/  environment/  vehicle/
├── assets/
│   ├── originals/a3/a3f9…c1.png  content-addressed, sharded by first 2 hex chars
│   ├── thumbs/a3/a3f9…c1.webp
│   └── meshes/7b/7b21…04.glb
├── generations/2026-07/<ulid>.json
└── .wobu/
    ├── sessions/<session-id>.json  heartbeats — who else has this open
    └── tmp/                        staging for atomic writes

Markdown is the source of truth. Frontmatter holds the ID, kind, links, attributes and tags; the body holds ## Notes and ## Description. You get git history on your world, external editing (Obsidian works on this folder as-is), trivial backup, and no migration dread.

Rules that keep the folder portable

No absolute paths The same share is /Volumes/art/Ashfall.wobu on one machine and Z:\art\Ashfall.wobu on another. Everything internal is relative.
Content-addressed assets Two people importing the same reference produce the same file. Dedup is free and asset writes never conflict.
Conservative filenames Lowercase ASCII slugs, nothing Windows or a case-insensitive SMB share would reject, and shallow nesting to stay under path-length limits.
No symlinks They don't survive SMB, zip, or most sync clients.
Write-once generations ULID-named, never mutated. Append-only means no conflict surface.
No secrets, ever Keys are in your OS keychain. project.json records only which provider a project prefers.

Where the index lives, and why it isn't here

~/.local/share/wobu/index/<project-ulid>.sqlite   (Linux; equivalents elsewhere)

Search, backlinks and graph traversal need an index, and SQLite is the obvious choice — but it must not sit inside a folder that's expected to live on a network share. SQLite's locking relies on advisory locks that are unreliable-to-broken over SMB and NFS, and the documented failure mode is corruption, not an error. WAL mode doesn't work on network filesystems at all. And sync clients will happily copy a half-written database mid-transaction.

So it lives in local application data, keyed by the project's ID rather than its path — which means it survives the share being remounted somewhere else. Copy a project folder to a machine that has never seen it and nothing is lost; the first open just rebuilds.

Troubleshooting

Symptom Try
Search misses something you know is there Settings → Storage → Rebuild index.
A node shows as corrupt Reveal it and open the file in a text editor — usually broken frontmatter from a hand edit or a sync client. Wobu won't overwrite it until it parses.
Everything went read-only Check share permissions. Wobu detects a read-only folder on open and says so in the title bar.
Banner says the share is offline Wobu is retrying with backoff. The UI stays readable from the index; writes resume when the mount returns.
Enhance or Generate is disabled No key on this machine for the selected provider, or the folder is read-only. Settings → Providers.
Generate errors on a working Gemini key Image models need billing enabled; text is free. See Providers.
Mesh auth fails for no reason Check your system clock — signatures expire after five minutes of skew.
Editing feels laggy on a NAS Raise the autosave delay in Settings → Editor.
Something needs reporting Settings → Diagnostics. Raise the log level, reproduce, then read the tail in-app before you send it — keys are redacted, but you should still see what you're handing over.

Glossary

Node Any entity in the world. Species, character, prop, and the two singletons all share one record type.
Kind What a node is. Selects its icon, colour, description sections and default relations.
Singleton Style Guide and World Canon — one per project, pinned above the rule.
Link An influence edge between nodes, with a role and a weight.
Layer One rung of the resolved stack: style, world, ancestry, culture, place, subject, shot.
Fragment One piece of text or one image contributed by a layer, with a weight and a routing target.
Influence Stack The resolved, ordered set of layers feeding the current generation.
Compiled prompt The final prompt string, tinted by contributing layer.
Influence snapshot The exact resolved stack saved with a generation, making it reproducible later.
Role What a reference image is for — silhouette, palette, material, mood, pose, costume, full ref.
Stale A description whose notes or upstream layers changed since it was enhanced.
Preset An output recipe — which sections to boost, framing, aspect, image count.
Pinning Promoting a generated image to a reference on its node, so it feeds the next generation.
Ticket A backend credential for peer-to-peer project sync. Creating or accepting one from the UI is planned in #109.
