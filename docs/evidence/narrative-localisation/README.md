# Native localisation acceptance

These screenshots and observations come from the real Tauri GTK/WebKit application on Linux,
using final backend `6aad208` and the original Harbor Voices fixture generated by `wobu-store`'s `localisation_fixture`
example. They are separate from the mocked frontend tests. No provider was called.

The fixture contains 20 stable source strings across bark, ambient, reaction, codex, quest summary
and journal assets, with real character/world records. Initially all source wording was approved,
current and locked; French translations were Draft and Arabic translations were Approved. One
line contains named placeholders, a newline and quotation marks. Test-prefixed translations are
fixture data, not a claim of translation quality.

## Observed native actions

- The real **Export locale** save dialog wrote a French CSV file outside the project. A native
  command also exported JSON. Repeated exports were byte-identical for each format; all 20 IDs,
  source revisions and metadata survived parsing, including the quoted multiline row.
- The dialog preview reported `unknown_id`, `duplicate_id`, `missing_id`, `placeholders`,
  `stale_source` and `translation_conflict`. **Import eligible rows** applied exactly 15 of 20
  source rows and preserved existing French/Arabic history. An old German translation guard
  subsequently refused to overwrite a newer imported version.
- The actual **Approve translation** row action appended a separate Approved version after Draft.
  All 20 French translations were then approved through the row buttons; source wording did not
  change.
- Native inspection verified `direction: rtl` for both Arabic plural forms even though the text
  starts with `{name}`. The category label is outside the direction-bearing paragraph; stored
  characters are unchanged. Both forms and preserved newlines are visible.
- Themes were verified using actual computed body colors: dark `rgb(13, 14, 18)` and light
  `rgb(238, 235, 230)`. Screenshots were inspected before labeling them.
- At the supported 960 × 620 minimum, the sheet measured 928 × 574 and had no horizontal content
  overflow. At 150% UI scale it measured 912 × 550, also without horizontal overflow. The Close
  action worked with keyboard focus and Enter. The window was restored to 1440 × 900 and 100%.

## Release, fallback and source freshness

The final backend run completed the remaining steps:

- **Release** passed and the real Export dialog published 20 strings after French and Arabic
  approvals. Requiring absent `de-CH` then blocked Release with 20 `missing_translation` diagnostics.
  Enabling explicit fallback in Localisation made Release pass. The exported `locales.json`
  identified one approved German fallback and 19 English source fallbacks; no sibling-region
  substitution occurred.
- A native command configured source locale `fr` with missing required `ja` for a separate
  Development export. Its manifest retained `locale: fr` and `strings/fr.json`, with no
  `strings/en.json`. The prior policy was restored afterward. This tests locale identity retention,
  not the linguistic quality of the fixture's source wording.
- The real shared Review **Unlock wording** action made the selected translations stale without
  deleting versions. **Lock wording** restored source readiness but did not revive old translation
  freshness. Review's Arabic **Translation out of date** production filter showed exactly one line.
- Shared Review editing changed that line's wording while preserving its stable ID. Source approval
  and locking did not rebind its translations. A fresh French JSON import, followed by the separate
  approval button, retained four versions (original Draft/Approved, new Draft/Approved). The old
  Arabic version still correctly blocked the final Release check.
- Native JavaScript errors remained empty. Final window state was 1440 × 900, 100% scale, with
  dialogs closed. These functional checks ran alongside repository Rust gates and make no quiet
  performance claim.

## Verification boundaries

N5 is excluded. Rust reference/package tests exercise locale lookup, explicit fallback and
host-selected plural rendering; these native Wobu captures do not claim Unity, Godot, Unreal or
Yarn adapter conformance. Formatting and locale-tag limits are documented in
[Revision-aware localisation](../../37-narrative-localisation.md).
